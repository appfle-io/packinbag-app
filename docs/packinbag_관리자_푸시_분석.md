# 관리자 푸시 발송(공지 · 마케팅) + 광고 수신 동의 — 분석 (2026-10-19 · master)

상태: **분석만, 미착수.** 사용자 결정(아래 "정할 것")을 받은 뒤 설계 · 구현한다. 법 관련 내용은 공개 안내서를 정리한 것이고 법률 자문이 아니다.

## 1. 지금 있는 것

- 푸시는 **iOS 1.5 이상 앱에만** 간다. Cloud Functions가 APNs로 직접 보냄(`functions/src/apns.ts`), 받을 기기는 `deviceTokens/{hash}`의 `apns`(token · env · alerts)가 있는 문서(`devices.ts` `devicesOf` · `sendToDevices`, 죽은 토큰 자동 정리)
- 웹 · PC · 포터블 · 안드로이드(아직 없음)는 푸시를 못 받는다 → 그 사람들에게는 앱 안 알림함(알림 종)이 유일한 길
- 지금 보내는 것: 함께 쓰는 가방 소식 · 맡긴 아이템 · 새 멤버(서비스 알림, 기본 켜짐), 테스트 알림. 설정 문구 "광고·이벤트 알림은 보내지 않아요"(SET-PUSH-07), 10/10 결정 "광고성 없음"
- 관리자 사이트: 대시보드 · 유저 조회 · 문의 · 이용권 · 공지 · 활동 로그. 공지는 앱 안 시트(앱을 열 때)로만 보임

## 2. 규칙(꼭 지킬 것)

### 공지(정보성)
- 서비스 변경 · 점검 · 약관 · 장애 같은 **이용 안내**는 광고 동의 없이 보낼 수 있다
- 단, 공지라는 이름으로 이벤트 · 할인 · 새 기능 홍보를 섞으면 전체가 광고가 된다 → 관리자 화면에서 "공지"를 고르면 안내 문구로 경고

### 마케팅(광고성, 정보통신망법 제50조 · KISA 앱 푸시 광고 안내서)
- **사전 동의(옵트인)**: 따로 묻고, 기본값은 꺼짐(미리 체크 금지). iOS 알림 허용 ≠ 광고 동의
- **야간(21시~다음 날 8시)**: 별도 야간 동의가 없으면 보내지 않는다
- **표시**: 제목 맨 앞 "(광고)" + 보내는 이(팩인백) + 끝에 수신거부 방법("설정 > 알림에서 끌 수 있어요")
- **철회 · 거부**: 앱 안에서 언제든, 로그인 같은 추가 절차 없이. 동의 · 거부 · 철회를 받으면 **14일 안에 처리 결과(날짜 · 결과)를 알림**
- **2년마다** 동의 여부를 다시 알림(최초 동의일 기준, 광고와 따로)
- 동의 기록(언제 · 어디서 · 켬/끔)과 발송 기록을 남긴다
- App Store 가이드라인 4.5.4: 광고 푸시는 앱 안에서 명시적으로 동의받고, 앱 안에서 끌 수 있어야 한다
- 개인정보 처리방침에 "광고성 정보 전송(선택)" 목적 · 항목 · 보유 기간 추가 필요

## 3. 제안 설계

### 데이터
| 위치 | 내용 |
|---|---|
| `users/{uid}.marketing` | `{ push: bool, night: bool, agreedAt, updatedAt, source: "signup" \| "settings" \| "recheck" }` — 본인만 쓰기(규칙: 값 모양 · `updatedAt == request.time`) |
| `users/{uid}/consentLogs/{auto}` | 바뀔 때마다 한 줄(증빙). 본인 create만, 수정 · 삭제 불가 |
| `users/{uid}.pushPrefs.notice` | 공지 알림(기본 켜짐, 끌 수 있게 — 선택) |
| `pushGroups/{id}` | `{ name, uids[], createdAt, updatedAt }` — 마스터만 |
| `pushCampaigns/{id}` | `{ type: notice \| marketing, target: { kind: user \| group \| all, ids }, title, body, link?, status, counts: { users, eligible, devices, sent, failed }, createdBy, sentAt, scheduledAt? }` — 서버만 쓰기, 마스터 읽기 |

### 보내기(서버)
- Functions 호출형 `adminSendPush`(마스터 확인 = `checkIsMaster`와 같은 기준) 또는 `/api/admin/push`
  1. 대상 uid 모으기: 특정인(유저 조회에서 고름) / 그룹 / 전체(`deviceTokens`에서 apns 있는 문서 = 실제로 받을 수 있는 사람만 읽음 → 읽기 최소)
  2. 거르기: 마케팅 = `marketing.push == true`(+ 지금이 야간이면 `night == true`, 아니면 8시로 예약), 공지 = `pushPrefs.notice != false`
  3. 마케팅이면 제목 앞 "(광고) 팩인백 · " · 본문 끝 수신거부 안내를 **서버가 붙인다**(빼먹지 않게)
  4. `sendToDevices`로 나눠 보내고 결과를 `pushCampaigns`에 · 활동 로그(audit)에
- 보내기 전 "미리 보기": 대상 N명 → 조건 맞는 사람 M명 → 받을 기기 K대(웹 · PC 사용자는 0대로 보임)
- "나에게 먼저 보내기"(테스트) 버튼
- 예약 발송(선택): 이미 쓰는 Cloud Tasks(`tasks.ts`)로
- 누르면 열 곳(선택): 공지 시트 · 특정 화면. 웹 쪽 알림 누르기 처리(`lib/v2/bagReminders.onBagNotificationTap`)에 새 kind를 추가 — **새 iOS 빌드 없이 될지 확인 필요**(알림 누르기를 웹이 받는지)

### 동의 받기(앱)
- 가입: 첫 프로필 화면(`ProfileSetupV2` — 이메일 · Google · Apple 가입이 모두 거침)에 체크 칸 "(선택) 이벤트 · 혜택 알림 받기 — 광고성 정보 수신 동의" + 펼치는 안내(무엇을 · 어떻게 · 끄는 곳). 기본 꺼짐
- 설정 > 알림: 토글 "이벤트 · 혜택 알림 (광고)" + 아랫줄 "2026.10.19 동의함" / "동의 안 함". 켜면 야간 동의를 따로 물을지(정할 것). 바꾸면 토스트로 처리 결과("2026년 10월 19일 광고 알림 수신에 동의했어요") — 14일 통지 의무를 화면에서 바로 충족. 웹 · PC에서도 보이게(계정 설정이라)
- 기존 가입자: 기본 꺼짐. 원하면 한 번 묻는 시트(정할 것)
- 2년 재확인: 서버가 매일(기존 스케줄러에 붙여) `agreedAt`이 2년 된 사람에게 안내 알림/앱 안 알림
- 설정 문구 SET-PUSH-07 "광고·이벤트 알림은 보내지 않아요"는 바꿔야 함

### 관리자 화면
- 메뉴 "푸시 보내기": 유형(공지 / 마케팅) → 받는 사람(특정인 · 그룹 · 전체) → 제목 · 본문 · 열 곳 → 미리 보기(위 숫자 + 실제 알림 모양) → [나에게 먼저] [보내기](확인 시트)
- 메뉴 "받는 그룹": 만들기 · 이름 · 사람 넣고 빼기(유저 조회 검색 재사용)
- "보낸 기록": 날짜 · 유형 · 대상 · 보낸 수 · 실패 수

## 4. 비용 · 범위
- Firestore: 발송 1번 = 대상 기기 문서 + 대상 users 문서 읽기(지금 가입자 규모면 몇십 건). 동의 토글은 쓰기 1~2건
- 바뀌는 곳: 웹(가입 · 설정 · 관리자 3화면), Functions(발송 · 재확인), firestore.rules, 개인정보 처리방침, FAQ · 사용설명서 · 마케팅 문서 · App Store 개인정보 항목(필요하면)
- iOS 새 빌드: 보이는 알림 자체는 지금 앱으로 받음. 누르면 열 곳 처리만 확인 필요

## 5. 단계(권장)
1. 동의 받기(가입 · 설정 · 기록 · 규칙 · 처리방침) — 먼저 내야 나중 광고가 합법
2. 공지 발송(특정인 · 전체) + 미리 보기 · 나에게 먼저 · 기록
3. 그룹 · 마케팅(표시 자동 · 야간 차단) · 예약 · 2년 재확인

## 6. 정할 것(사용자)
1. 야간(21~8시) 광고: A 보내지 않고 8시로 미룸(야간 동의 안 받음, 추천) / B 야간 동의도 따로 받기
2. 공지 알림을 사용자가 끌 수 있게 할지(추천: 끌 수 있게, 기본 켜짐)
3. 기존 가입자에게 광고 동의를 한 번 물을지(추천: 앱을 열 때 시트 1회, "나중에" 가능)
4. 웹 · PC 사용자: 앱 안 알림함에도 같이 넣을지(추천: 공지는 같이, 광고는 푸시만)
5. 그룹: 직접 고른 목록만(1차) vs 조건 그룹(최근 7일 활동 · 프리미엄 등)도
6. 예약 발송이 1차에 필요한지
7. 보내는 이 표기 · 연락처(광고 표시에 넣을 이름 · 문의처)
