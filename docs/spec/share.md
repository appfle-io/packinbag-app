기준 코드: v1.6.1 (2026-10-15). 멤버 시트 · 가방 공유 시트 화면 자체는 `bag.md`, 팩 · 폴더 공유 시트는 `packs.md`(PACK-SHARE), 메모 공유는 `memo.md`, 인원 · 참여 한도의 프리미엄 판정은 `premium.md`, 앱 브리지(카톡 → 앱)는 `native-ios.md`, 라우트 입력 · 실패 응답 목록은 `api.md`, 규칙 원문은 `security-rules.md`에서 다룬다.

## 1. SHARE-INV 초대

| ID | 규칙 |
|---|---|
| SHARE-INV-01 | 가방을 만들 때 서버가 초대코드(겹치지 않게 트랜잭션)와 보기 토큰을 만든다 |
| SHARE-INV-02 | 초대 링크 = `{origin}/?invite={코드}`. 멤버 시트의 "초대 링크 복사" · 초대 코드 "복사"는 **멤버 누구나**(그룹장만이 아님) |
| SHARE-INV-03 | 인원이 찼으면 링크 · 코드 대신 안내(그룹장만 인원을 알 수 있음 — 내 프리미엄 기준): 무료 한도 "무료로는 2명까지 함께 쓸 수 있어요."(넘친 상태면 "지금 멤버는 그대로지만 새로 초대할 수는 없어요.") + "프리미엄으로 10명까지" / 최대 "가방 인원이 가득 찼어요 (최대 10명)." |
| SHARE-INV-04 | 초대 코드 새로 받기(그룹장만): 확인 "초대 코드를 새로 받을까요?" / "기존 코드와 링크는 더 이상 쓸 수 없어요." → 서버가 빈 코드를 골라 가방에 쓰고 옛 코드 문서 삭제 + 감사 로그 → "초대 코드를 새로 발급했어요" |
| SHARE-INV-05 | 오프라인 모드는 "오프라인 모드에서는 초대할 수 없어요. 온라인 계정으로 전환하면 함께 쓸 수 있어요." 계정 모드에서 끊겼으면 인터넷 필요(offline.md OFF-GUARD-03) |

## 2. SHARE-JOIN 참여

| ID | 규칙 |
|---|---|
| SHARE-JOIN-01 | 길: 초대 링크(`?invite=` · `?join=`) / 홈 "코드로 참여하기" 시트("함께 쓸 사람이 보내준 초대 코드를 입력해 주세요." · 자리글 "예: AB12CD" · "참여하기") / `/v` 보기의 "참여하기"(주소에 `?code=`가 있을 때) |
| SHARE-JOIN-02 | 링크로 들어오면 주소의 코드를 sessionStorage에 두고 주소에서 지움 → 로그인 · 가입 · 첫 프로필까지 끝나면 자동 참여 → "초대 링크로 가방에 참여했어요!" + 그 가방 열기 |
| SHARE-JOIN-03 | 서버 검사 순서: 코드 문서 있음 → 가방 있음 → **가방의 지금 코드와 같음**(재발급된 옛 코드 · 위조 문서 거절) → 휴지통 아님 → (이미 멤버면 검사 없이 프로필만 갱신) → 인원 10명 미만 → 2명 이상이면 그룹장 프리미엄 확인 → 참여하는 사람 무료면 참여 가방 3개 미만 → 트랜잭션으로 한 번 더 확인하고 `memberIds`에 추가 + 프로필 스냅샷 |
| SHARE-JOIN-04 | 실패 문구: 코드 없음 · 옛 코드 "해당 초대코드의 가방을 찾을 수 없어요" / 가방 없음 · 휴지통 "가방이 삭제되었거나 존재하지 않아요" / 10명 "가방 인원이 가득 찼어요 (최대 10명)" / 그룹장 무료 "이 가방은 2명까지만 함께 쓸 수 있어요. 가방을 만든 사람이 프리미엄이면 10명까지 함께할 수 있어요." / 참여 한도(→ 프리미엄 시트) "무료로는 초대받은 가방을 최대 3개까지만 참여할 수 있어요. 더 참여하려면 프리미엄이 필요해요." |
| SHARE-JOIN-05 | 코드로 참여 시트는 실패하면 시트 안에 빨간 글로 이유를 보이고 닫히지 않음. 참여 한도는 프리미엄 시트로 |
| SHARE-JOIN-09 | 틀린 코드(없음 · 옛 코드 · 가방 없음 · 휴지통 · 형식 틀림)는 계정마다 KST 하루 20번까지 → 넘으면 "코드를 너무 많이 틀렸어요. 내일 다시 시도해주세요"(10/16, api.md API-BAG-J-10). 앱은 `inviteCodes`를 직접 읽지 않는다(규칙으로 막힘) |
| SHARE-JOIN-06 | 그룹장이 탈퇴 등으로 계정이 없으면 무료로 판정(2명 한도) |
| SHARE-JOIN-07 | 게스트(익명)도 참여할 수 있음 |
| SHARE-JOIN-08 | 새 멤버가 들어오면 그룹장에게 서버 푸시(설정 "새 멤버 참여", native-ios.md) |

## 3. SHARE-MEM 멤버 권한

| ID | 동작 | 누가 | 규칙 |
|---|---|---|---|
| SHARE-MEM-01 | 가방 읽기 · 고치기 · 체크 | 멤버 누구나 | 규칙: `memberIds`에 있어야. 잠긴 가방(무료 한도)은 **그룹장만** 못 고침(다른 멤버는 그대로) |
| SHARE-MEM-02 | 멤버 내보내기 | 그룹장 | 확인 "{닉네임} 님을 내보낼까요?" / "다시 들어오려면 초대 코드가 필요해요." → "멤버를 내보냈어요". 규칙: 빼는 것은 그룹장 아무나 · 일반 멤버는 자기 자신만, 넣는 것은 서버만 |
| SHARE-MEM-03 | 그룹장 넘기기 | 그룹장 → 멤버 | 확인 "{닉네임} 님에게 넘길까요?" / "넘기면 나는 일반 멤버가 돼요. 함께 쓸 수 있는 인원은 새 만든 사람의 프리미엄 여부를 따라요." → 서버(`transfer-bag-ownership`): 지금 그룹장 · 대상이 멤버인지 확인 → `ownerId` 변경 → 두 사람의 가방 잠김 다시 계산 → "만든 사람을 넘겼어요" |
| SHARE-MEM-04 | 나가기 | 일반 멤버 | 확인 "이 가방에서 나갈까요?" / "다시 참여하려면 초대 코드가 필요해요. 가방과 다른 멤버의 내용은 그대로 남아요." → `memberIds`에서 나 · 내 프로필 스냅샷 삭제 → "가방에서 나갔어요". 홈에서 여러 개 골라 지울 때도 남의 가방은 나가기 |
| SHARE-MEM-05 | 그룹장이 나가기 | — | 버튼 없음. 그룹장은 넘기거나(→ 일반 멤버가 된 뒤 나가기) 가방을 지움 |
| SHARE-MEM-06 | 휴지통 · 완전 삭제 | 그룹장(완전 삭제는 혼자 남은 멤버도) | 휴지통은 그룹장 화면에서만 숨김, 다른 멤버는 그대로 봄. 완전 삭제하면 모두에게서 사라짐 |

| SHARE-MEM-09 | 목록 순서 | | 만든 사람 → 나 → 나머지. 줄: 캐릭터(접속 중 점) + 닉네임 + "만든 사람" · "멤버" + "나" · "지금 보는 중". 그룹장에게만 다른 멤버 ⋯(넘기기 · 내보내기) |

## 5. SHARE-PACK 팩 · 폴더 · 메모 공유 (`/p/{토큰}`)

| ID | 규칙 |
|---|---|
| SHARE-PACK-01 | 만들기 · 갱신(`share-pack`): 서버가 **저장된 곳에서 읽은 토큰만** 다시 씀(클라이언트가 보낸 토큰은 안 믿음). 그 스냅샷의 주인이 나이거나, 같은 가방의 같은 팩에서 만든 것일 때만 덮어씀 → 아니면 새 토큰. 가방 속 팩이면 멤버여야 함 |
| SHARE-PACK-02 | 새 토큰은 가방 속 팩이면 트랜잭션으로 그 팩에만, 보관함 팩이면 보관함 문서에 저장. 스냅샷 저장 뒤 `/p/{토큰}` 캐시를 비움 |
| SHARE-PACK-03 | 폴더 공유는 하위 폴더까지 한 묶음으로(parentId로 구조 유지, 10/15). 보기는 하위 폴더 경로("캠핑 / 조리")로 묶어 보여 줌 |
| SHARE-PACK-04 | 보기(v2, `GuestPackViewV2`, 10/15): 없는 토큰 "공유가 끝났거나 없는 팩이에요" / "링크가 만료됐거나 공유가 꺼졌어요." · 메모 하나면 글 읽기 화면 · 그 밖 팩 카드(아이템은 체크 표시만, 메모는 다섯 덩어리까지 + "전체 보기" · "복사") + 아래 "가져오기" |
| SHARE-PACK-05 | 가져오기: `/?importPack={토큰}` → 로그인 뒤 `import-shared-pack` → 무료면 한도 검사(폴더는 1 + 팩 수) → 폴더면 "{제목}" 폴더 하나 + 그 안에 팩들, 팩이면 맨 위에 하나. 아이템 · 팩 모두 새 id, `locked` · `isQuickPack` 같은 서버 필드는 뺌 → 팩 탭으로 + "\"{이름}\" 팩을 보관함으로 가져왔어요!" / 한도 초과 → 프리미엄 시트 / 그 밖 "팩을 가져오지 못했어요." |
| SHARE-PACK-06 | 공유 시트 "공유 끄기" → 확인 "공유를 끌까요?" / "이 링크는 더 이상 열리지 않아요. 다시 공유하면 새 주소가 만들어져요." → `unshare-pack`(스냅샷 삭제 + 원본 토큰 떼기) → "공유를 껐어요". 팩 · 폴더 · 가방 완전 삭제 · 30일 자동 삭제 · 탈퇴 때도 스냅샷을 지움. 편집기를 나갈 때의 자동 갱신은 `refreshOnly`(살아 있는 공유만 고침) → 끈 공유가 되살아나지 않음(10/15) |
